SECTION 02

Knowledge Agent：智能注入蓝队推理链

Knowledge Agent 来自 CyberOrion 项目的 KnowledgeInjector 组件。它只对蓝队角色（triage / threat_hunter / host_harden）开放，红队严禁调用——从权限层到测试层均硬性隔离。

蓝队 Agent 角色

每个蓝队子 Agent 在执行意图前都会调用 KnowledgeInjector 检索知识。

  • triage · 告警分诊：判断告警真伪与严重度
  • threat_hunter · 威胁狩猎：基于 IOC/技术编号搜索历史活动
  • host_harden · 主机加固：检索对应 ATT&CK 缓解措施

红队（red / 渗透测试）严禁调用——SecurityError 立即抛出，确保红队完全凭训练知识决策。

知识库设计

Knowledge Agent 后端是多源异构的知识库集合：

  • attack_kb.jsonl · MITRE ATT&CK 企业矩阵（8126 文档）
  • enterprise-attack.json · ATT&CK STIX 完整定义
  • cve_critical.json · 关键 CVE 情报
  • regulations.json · 中国法律法规（已对接三法一条例）
  • sandbox_knowledge.json · 靶场环境知识
  • malpedia_families.json · 恶意软件家族

PhishingDetector 内置 kb_entries（60+ 条）作为 attack_kb 的钓鱼专项补强：法律法规、近期案例、攻击手法、防御指南。

SECTION 03

检索策略与字符预算

Knowledge Agent 的工程约束确保检索既全面（双路互补）又可控（字符预算），让蓝队推理不会因为 RAG 而变得臃肿或拖沓。

双路检索策略 DUAL-PATH

Path A 精确查用于技术编号（T1566.001 等），命中权重极高；Path B 语义查覆盖意图关键词与中文长句。两者结果按 doc id 去重合并。

Path A · 精确查kb.lookup(tid)
Path B · 语义查kb.search(q, k=3)
embedding 模式cosine · npz cache
回退 BM25idf + CJK bigram
技术编号加权TID_BOOST = 100.0
嵌入模型text-embedding-v3

字符预算与角色策略 BUDGET

不同蓝队角色对应不同字符预算——避免提示词被知识库内容淹没，也避免关键信息因截断而丢失。

blue · 蓝队响应2500 chars / 8 docs
host_harden · 主机加固1800 chars / 6 docs
截断阈值剩余 < 100 字则丢弃该块
命中策略全量命中后再贪心截断
失败事件rag_unavailable vs rag_no_match
中文标题zh_translations.py 静态映射

前端可视化事件 SSE

每次检索都会通过 SSE 实时下发事件，前端可按 doc id + 中文标题 + 命中正文逐条展示，让分析师看清"AI 是依据什么知识做出判断"。

rag_retrieval命中 + 完整 doc 列表
rag_no_matchKB 中无相关条目
rag_unavailableKB 索引不可用
前端组件KnowledgeView.tsx · KbGraph.tsx
展示样式紫色边框 + 可展开正文
trace 状态查询/角色/意图/命中条数

安全边界与红蓝隔离 SECURITY

KnowledgeInjector 在代码层、调用层、测试层三重保证 RAG 仅供蓝队使用——这是为了保证"红队完全凭训练知识与现场侦察决策"，不因 RAG 注入而获得不公平优势。

代码层白名单ALLOWED_SIDES = {blue, host_harden}
违规异常SecurityError(PermissionError)
红队系统提示明确禁止 KB 检索段落
测试覆盖test_knowledge_injector_rejects_red
工具调用校验tool_call messages 不含 RAG 段
审计SSE 事件含完整 side 字段
